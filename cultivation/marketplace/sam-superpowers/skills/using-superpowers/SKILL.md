# Using skills

Skills exist for common workflows (brainstorming, TDD, debugging, plan writing, code review).
Prefer one when it clearly fits the task at hand; read it before acting, then follow or adapt it with judgment.
You decide whether a skill applies - there is no mandatory pre-check and no penalty for working without one.
The user's explicit instructions (CLAUDE.md, AGENTS.md, a direct request, or an explicit `/skill-name`) always win over any skill.
When two skills overlap, pick the one that determines HOW to approach the work (process) before the one that guides execution.
