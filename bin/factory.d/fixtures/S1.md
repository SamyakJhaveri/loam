## Goal and why
One check command exists and is green on the current tree, CI runs the same command on push and on pull requests, and a publish-only release workflow replaces the verify-on-tag workflow.
Nothing is deleted yet.
This is `DESIGN.md` law 4 and law 6, and commit 1 of `.superpowers/lean-v3/02-IMPLEMENTATION-SPEC.md`.

The standing list. Except: bin/check, .github/workflows/test.yml, .github/workflows/release.yml, .github/ci/python-requirements.txt, bin/tests/test_ci_configuration.py, bin/rendered_harness_contract.py, bin/tests/test_rendered_harness_contract.py (this ticket creates or rewrites them).

Deleting `bin/verify-template.sh` or any other verification script.

Creating a `requirements-dev.txt`; the pins go in the existing `.github/ci/python-requirements.txt`.
Any change to `seed/`.

## Approach
`bin/check` is about 95 lines and the spec carries its full text.
It defaults `LISTING_BUDGET` to 2750, the current ratchet; a later ticket lowers it.
Its `claude plugin validate` targets are hard-coded: `seed/.claude` non-strict, `seed/.agents/skills` and `cultivation/marketplace` strict.
Done check `ci-config` and done check `verify-template` contradict each other through one file, `bin/rendered_harness_contract.py`, whose `_check_release_callers` asserts marker positions in `test.yml` and `release.yml` that still name verify-template.
This ticket therefore owns exactly that assertion.
In `_check_release_callers`, remove the two `_check_marker_positions` calls for `test.yml` and `release.yml` and keep the third call for `bin/release.sh`.
Update or remove the matching expectations in `bin/tests/test_rendered_harness_contract.py` so that module still passes.
Touch nothing else in either file.
