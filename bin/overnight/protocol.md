## Steps for one PR

1. **Pick.** `gh pr list --repo SamyakJhaveri/loam --state open --json number,title,isDraft,headRefName,body,labels` and take the oldest PR the factory opened (its body has the factory's sections and `Closes #<issue>`) that has no line in `O/log.md` ending `merged` or `left open`. None: append "idle <UTC time>" to `O/log.md` and stop.
2. **Read.** The issue body (`gh issue view <issue>`), the PR body (graders' verdicts, the in-run Codex review, the check output), and the diff (`gh pr diff`). Note every Critical, High and Medium finding already listed.
3. **Panel, in parallel, each blind to the others and given the ticket and the diff, not your opinion:**
   - Codex: review design, implementation and testing; findings with severity Critical, High, Medium or Low, each with `file:line` and a failing scenario; write to `O/pr-<n>-codex.md`.
   - Fable (`escalate` agent): the same brief, independently; also "is the approach right, or is there a better design?".
   - Surprise-me (an Opus `worker`), only on the first PR of each night (Pacific date; no earlier surprise-me that night in `O/log.md`) and on a design-heavy ticket (a new mechanism, or a change to how runs, graders, the slot or the driver work); otherwise skip it and say which in `O/log.md` (Samyak's ruling, 30 Oct 2026, review-value audit option 1: Fable stays on every PR; the Codex panel stays on every PR for a two-night trial on gpt-6.1-sol): read `~/loam/cultivation/marketplace/sam-cc-setup/skills/surprise-me/SKILL.md` by path and follow it in Solo mode on this ticket's goal; it may search the web for better solutions; return at most three ideas, each with cost and proof.
4. **Verify.** One Opus `scout` per reviewer's list: reproduce or reject each finding (CONFIRMED, REJECTED, PARTLY, with evidence). Only confirmed or partly confirmed findings go forward.
5. **Fix.** One Opus `worker` on the PR branch, in its own detached worktree (`git -C ~/loam fetch -q origin <branch> && git -C ~/loam worktree add --detach ~/.local/state/loam/worktrees/overnight-<n> origin/<branch>`; the branch itself is checked out in the factory's ticket worktree `~/loam-<issue>`, so git refuses a second checkout of it), pushing with `git push origin HEAD:<branch>`: fix every confirmed Critical, High and Medium finding with the smallest change that removes the cause, plus a test only where it guards real behavior; run `bin/check` until it prints `check: PASSED`; commit and push the branch (no force). Low findings and surprise-me ideas that change scope go to `O/followups.md`, not into this PR.
   **Bugs that were already there (Samyak's ruling, 30 Oct 2026, 11:30 Pacific).** A confirmed Medium-or-worse bug that predates this PR, in the files or code paths this PR touches, is fixed in this same PR whenever the fix is feasible, Low ones too where cheap: the worker already has the context, and a separate issue costs a fresh agent the tokens and time to re-learn it. His words: "if it's possible to fix those bugs, it's best to do it then because the agents have an idea and context of that particular bug working on that particular set of files." File it as a new issue instead only when the fix is large or reaches code this PR does not touch, and say why in `O/log.md`. Calling a finding "pre-existing", "out of scope" or lowering its severity needs a verifier scout's evidence, never your own reading alone.
6. **Re-review the fix.** One more Codex read-only review of the fix commits only, verified the same way (a re-review finding is downgraded or rejected only on a verifier scout's evidence, never on your own reading); repeat steps 5 and 6 at most twice more, or at most once more when the finding is in heuristic or text-parsing code (a matcher reading English, a regex over prose), which did not converge on #441. Still a Medium or worse after that: leave open (step 9).
7. **Learn, so the next ticket goes better** (before the merge gate, so the lesson merges with the PR that taught it). Work in your detached worktree `~/.local/state/loam/worktrees/overnight-<n>`, made with step 5's `fetch` and `worktree add --detach` commands if step 5 made none. First bring the branch up to date, since the next ticket is built while you review (31 Oct) and every merged PR adds a lesson: if it is behind `origin/main` (`git merge-base --is-ancestor origin/main HEAD` fails), merge `origin/main` into it there, resolve any conflict keeping both sides' intent, run `bin/check`, and push with `git push origin HEAD:<branch>`; a conflict you cannot resolve with confidence is a Medium finding (step 9: left open). Then add a section `## From PR #<n> (issue #<issue>), <UTC date>` at the end of `~/.local/state/loam/worktrees/overnight-<n>/docs/factory/LESSONS.md`, with what this PR taught (a failure mode, a missing check, a better approach), each with evidence, and commit and push it on the branch the same way, so step 8's checks and head sha include it.
