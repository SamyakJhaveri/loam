## Original engineering evidence and its proper use

The paragraphs in this section distinguish source facts from proposed Loam policy. Article-reported performance is not reproduced evidence for Loam.

### Effective harnesses for long-running agents

Verified: the [original article](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) describes an initializer, a comprehensive feature inventory initially marked failing, incremental coding, recoverable progress, startup checks and user-level browser verification. It presents one solution for web applications, with specialized multi-agent work and other domains left open. Its initializer and coder differ in initial prompt; the footnote says their system prompt, tools and harness otherwise match. The inspected scope covers substantive article body through future work and the footnote.

Design inference: initialize an explicit obligation inventory with unknown/unverified status and preserve the original request. A resumed worker rechecks baseline health and reopens relevant evidence before acting. One feature per session is a demonstrated technique for that setup, not a permanent native-host contract. Do not equate an initially false field with a regression test that has actually failed on the base candidate. Those are different evidence types.

### Harness design for long-running application development

Verified: the [later original article](https://www.anthropic.com/engineering/harness-design-long-running-apps) removes context resets, then removes sprint decomposition as models improve. It keeps useful planning and evaluation. Reviewer calibration requires inspecting traces and revising criteria; judgment remains imperfect, and later outputs can be worse than intermediate outputs. Generator and evaluator negotiated testable contracts before implementation in the earlier version. Scope covers the substantive body, comparison narratives/tables, simplification results and appendix sample plan.

Design inference: separate plan/criteria admission from worker execution, without dictating microsteps. Preserve native worker continuity. Keep independent candidate review where admitted method requires it, calibrated against actual failure cases. Retain candidate snapshots so selection is evidence-based rather than simply last-result-wins. Broader scope proposed by a planner, including added AI features in the article's example, still needs to fit user authority. Ablate obsolete scaffolding individually; do not remove acceptance or authority boundaries as a performance experiment.

### Multi-agent research system

Verified: the [original article](https://www.anthropic.com/engineering/multi-agent-research-system) supports adaptive inquiry, explicit delegated objectives/output/tool guidance/boundaries, source-quality judgment, outcome-based evaluation, recovery from checkpoints and direct filesystem artifact handoff. It reports coding dependency constraints and a historical synchronous coordination bottleneck. Its token multiplier compares multi-agent work to chats, not directly to single-agent coding; its scaling examples are heuristics. Scope covers substantive article and appendix.

Design inference: a native lead can expand investigation within scope, delegate independent branches, retain reports before synthesis and revisit sources directly. Evaluation covers requested scope, source support and unresolved contradictions. A fixed small fan-out ceiling is a Loam policy choice, not the source's universal rule. Expected research-branch identities and missing-result accounting belong in the supervisor; the exact investigation path belongs to the native lead.

### Building effective agents

It gives dynamic coding/search orchestration and evaluator-optimizer patterns. Tool descriptions, useful errors, examples and unambiguous arguments matter. Smaller-model routing is an example, not a requirement. Scope covers workflow/agent taxonomy, all pattern sections and both appendices; no linked implementation was executed.

Design inference: support inquiry, deliberation, experiment and engineering methods inside one operational lifecycle. Mechanical result validation is code; hypothesis choice and tool sequencing remain native agency. The user-selected roster and effort override cost-routing examples. A structured verdict is a transport contract, not proof of its contents.

### Managed Agents engineering

Verified: the [original article](https://www.anthropic.com/engineering/managed-agents) separates durable session events, reasoning harness and execution environment. Stored events can be reopened after compaction. It explicitly describes obsolete reset machinery and credential isolation outside generated-code execution. Scope covers the substantive article and interface examples.

Design inference: retain source evidence and raw observable native events separately from context summaries. Loam's SQLite state and artifact archive surround the native host; they do not recreate its inference loop or require the hosted service. Resume identity, deployment revision and actual outstanding jobs must survive supervisor restart. A native session ID alone cannot certify a safe retry.

## Finalized connection design amendments

Recommendation: apply these clauses to the accepted SQLite/artifact and native-adapter architecture. They resolve concrete gaps; they do not reopen the native-driver or every-seed decisions.

**Factory distribution and entry.** Every generated project receives its own runtime, schema migrations, artifact contract, local supervisor, fixture suite and on-demand research/engineering/review methods. Shared entry skills live under the existing `seed/.agents/skills/` distribution mechanism. Keep the root entry prose short and point to deeper local docs. Personal caches, optional plugin installation, another checkout and a hosted supervisor cannot be required to complete a normal local run. Validate this in a clean generated project with personal skill/plugin caches unavailable. Domain tools remain explicit project readiness dependencies.

**Original obligation and current plan.** Persist the user's original request, constraints and amendments as immutable source artifacts. Record a revisioned obligation population separately from the agent's current plan. Native leads choose decomposition and can propose altered scope; a planned deliverable never silently replaces an original obligation. Research can conclude negative or inconclusive when that satisfies the admitted method. Checks distinguish unverified requirement, reproduced base failure, candidate test result and reviewed support.

**Long-running native session.** The operational lifecycle admits work, creates a native attempt, observes it, collects a candidate and validates it. It does not prescribe one feature or one session per obligation. Continue a compatible native worker session after checkpoints and compaction. Recovery revalidates revision, native handle, effective model/effort, loaded assets, permissions and outstanding jobs. Restart only for a justified isolation/capability/recovery reason. Raw evidence remains reopenable after summaries expire.

**Native goals, advisors, adversarial work and review.** A native goal keeps the worker pursuing admitted work. An advisor helps the worker choose a path. An adversarial collaborator tries to break a proposal or implementation. An independent reviewer assesses a named candidate against fixed required criteria. These roles are not interchangeable. A consulted advisor is not independent acceptance simply because it uses another model. A fresh reviewer may use the same allowed model if role/context independence is established. The original lead cannot become independent by renaming itself. Use native mechanisms rather than a fabricated provider-agnostic simulation; unavailable required capability blocks that profile. Auxiliary model observations remain required by the established roster contract.

**Candidate/evidence handoff.** Give the reviewer original requirements, current admitted criterion identities, candidate and baseline content identities, required dependency context and permitted source/experiment artifacts. Exclude producer private conversation from required independent review. Source observations distinguish request, tool success, artifact publication, inspection and claimed support. The supervisor verifies identities and completeness, while the evaluator judges actual criterion support. A nonempty evidence list, receipt digest, screenshot filename or approved boolean cannot stand in for this chain. Reviewers may exercise a faithful isolated copy when live behavior is part of the criterion.

**Status and selection.** SQLite owns authoritative obligation, attempt, reservation and acceptance transitions. Workers publish staging artifacts and proposed findings through the admitted interface; they do not directly write accepted status. Artifact publication and database references obey the accepted crash protocol. Distinguish transport completion, native goal result, candidate ready, review incomplete, rejected and accepted. Preserve prior candidates; a later regression does not erase a valid prior result, but an older result still needs checks against current criteria before selection. Empty or duplicate criterion coverage is not accepted. ABANDON records a disposition and reason; it does not silently satisfy a still-required user obligation.

**Interruptions and recovery.** Record a stop or material revision barrier before sending steering. User origin cannot come from text in a worker-writable file. Persist delivery identity and distinguish sent, acknowledged/queued and applied evidence. Reconcile live descendants before relaunch or acceptance. Replay of a committed receipt is different from native continuation and from repeating an external effect. Missing launch/result acknowledgment is an unknown outcome until readback or genuine idempotency resolves it. Continuing work never replenishes lifetime budget.

**Calibration and maintenance.** Store reviewer failure cases and native prompt/tool revisions. Proposed improvements cite a concrete failure, evidence and expected remedy. Evaluate representative work and held-out counterexamples before changing admitted methods. Remove obsolete worker scaffolding individually. Maintain a source-to-rule dependency record so a changed upstream guide can trigger review, not automatic policy mutation. Scheduled discovery is locally authorized and produces ordinary work records; it does not bypass the factory's authority or acceptance contract.

## Acceptance scenarios to add to the implementation plan

These are scenario specifications for the existing proposed adapter/state test interfaces, not claims that those tests exist or passed.

| Scenario | Required observable result |
|---|---|
| Native worker continues across compaction while an independent reviewer is requested | Worker retains compatible continuity; reviewer has a distinct initial context and the complete candidate/criterion packet. Same model does not alone invalidate independence. |
| User changes scope during a feature, then a stale queued task completes | Original result retains its revision. Current acceptance is held or rejected. A stop cannot be deferred solely by the one-feature rule. |
| PreToolUse read marker exists, but Read fails | Only attempted-read status exists; no inspected/support receipt or acceptance is produced. |
| Worker supplies an unrelated image, old read log or its own well-formed automatic-evidence string | Evidence cannot authorize any unrelated criterion. Supervisor-owned execution origin and content bindings are checked. |
| Review says approved with no findings, duplicate findings, or omitted required criterion | Result is incomplete/invalid, even when its internal boolean/blocker consistency is satisfied. |
| Reviewer needs to validate a live interaction and the supplied screenshot looks correct | It exercises the admitted app candidate; a nonfunctional underlying interaction causes rejection. |
| Candidate or test helper changes without command text, line count or byte length changing | Old candidate/check receipts become stale. Full content and dependency identities govern reuse. |
| Supervisor dies after persisting a result but before acknowledgment | Restart adopts/reconciles the result under its existing identity; no second worker or duplicate settlement. |
| Worker subprocess survives pause or session exit | Job remains recorded and acceptance requiring quiescence stays blocked. No false claim that a tool-block file stopped it. |
| Budget store is corrupt or a native goal restarts its counters | Admission remains blocked/unknown or uses valid durable accounting; lifetime allowance does not reset. |
| A middle candidate is better than the last result | Prior artifacts remain available. Selection validates the chosen candidate against current criteria, rather than equating recency with quality. |
| Clean generated project lacks personal plugins and Loam developer checkout | Complete local factory/readiness/fixtures work from shipped assets. Missing declared external tools are precise readiness failures. |
| Model update makes a former reset/prompt workaround unnecessary | A proposed revision with representative evaluation removes the workaround while preserving user effort and authority/evidence contracts. |
