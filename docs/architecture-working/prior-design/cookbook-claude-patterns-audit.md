## Proposed seed integration homes and dependencies

Assumption: use these concrete homes unless the integration owner has already fixed a canonical equivalent:

- **K: mechanical factory.** `seed/bin/factory` with `seed/bin/factory.d/` modules; protected SQLite state plus separately retained artifacts. Own revision admission, task identity, attempts, leases, observation receipts, coverage reconciliation, deterministic checks, review acceptance, retry/stop/recovery, and outward-action authorization. Agents submit proposals; they do not write accepted state. No extra Messages API reasoning loop.
- **C: portable contracts.** `seed/docs/factory/` and schema files under the mechanical factory's canonical contract directory. Define task brief, role handback, source/claim evidence, review finding, consultation receipt, experiment record, continuation record, and model/effort/capability profile. One source of truth; native profiles reference it.
- **R: native research/engineering roles.** Shared skill material under `seed/.agents/skills/factory/` with supporting references for source acquisition, competing hypotheses, method design, experiment execution, replication, evidence review, and synthesis. Native Claude agent definitions live under `seed/.claude/agents/`; source shared role text once and verify mirrors if generated. Keep the Fable driver fully equipped with authorized tools and raw-source access.
- **W: native orchestration.** Saved, reviewed Claude workflows under `seed/.claude/workflows/`, for coverage audit and bounded independent review. The native Claude adapter launches/observes native work; the deterministic supervisor validates the resulting evidence. Ordinary native subagents remain suitable for adaptive work. Interactive teams are a separate admitted mode.
- **V: repeatable fixtures.** `seed/tests/factory/` plus a generated-project smoke runner. A proposed future command is `python3 -m unittest discover -s tests/factory`; it is not present or run in this audit. `bin/check` remains the repository release validation once implementation exists.

Dependencies: installed and explicitly admitted native Claude host/SDK; SQLite-capable local runtime; project tools required by its domain. No Managed Agents subscription, cloud sessions, MongoDB, embedding model download, notebook runtime, or extra Anthropic API controller becomes a seed prerequisite. Resolve Fable 5.1 driver and Fable 5.1/Opus 4.8 role identities with the user's selected effort; no economic model/effort substitution. Optional capabilities are still shipped as documented assets with explicit availability checks. A requested capability that cannot run is an unmet obligation, not a silent solo fallback.

## Independent adversarial work, concretely

Assumption: use a native Fable lead with distinct role prompts and context policies, rather than assuming every second agent is independent. Before the first committed plan, a premise checker verifies the task population, input provenance and assumptions. Independent method investigators receive the same immutable question and evidence access but not each other's drafts. They return their hypotheses, attempted falsifications, source references, tests or experiments, result, and unresolved questions. K captures these initial artifacts before any peer critique. The next stage exchanges the frozen claims and asks each investigator to identify a discriminating test or a concrete counterexample. Disagreement is resolved by source inspection or experiment, not vote count.

Assumption: a skeptical reviewer is allowed to say supported, contradicted, or unverified. Missing evidence is not contradiction. Fresh context does not mean blind restriction to another model's summary. For a check requiring replication, provide a writable isolated experiment directory and approved execution tools. For evidence review, protect accepted artifacts from modification. Keep the Fable lead able to inspect raw source passages and rerun a critical calculation; the no-tools coordinator in plan-big is explicitly rejected for this design.

Verified: the cookbook generated script supplies verifier reasoning to the skeptic. That is an adversarial review stage, not a blind independent first investigation. Its skeptic runs only on confirmations. Assumption: Loam declares the required review population explicitly: all acceptance claims and plan premises for acceptance review; negative findings also receive challenge when false rejection is material. A source-acquisition helper, advisor, hypothesis investigator, reviewer, and integration owner are different responsibilities. Do not collapse them into a generic reviewer role.

## Native capabilities that change the adapter design

Disabled/unsupported configuration can leave it unused. [Native advisor](https://code.claude.com/docs/en/advisor).

Assumption: advisor remains available for consequential judgment where admitted; no cost-based rule removes consult-before-done. Record actual occurrence separately from configuration. Assumption: the factory must admit an interactive-team route when the user requests that form of deliberation, or explicitly surface the unavailable capability. An SDK session with named subagents is a useful but different route. Record actual role/tool/skill application; do not infer it from a matching agent name. Native peer messaging is not human approval.

Verified: Workflow scripts coordinate native agents; they cannot directly use filesystem/shell or dynamically import modules. They have no mid-run user input; stage sign-off requires separate workflows. Same-session replay caches by agent start order, and changed/failed earlier calls invalidate later work. Assumption: admit a bounded Workflow stage whose intermediate artifacts and required population are fixed. For a consequential user method change, install K's barrier, stop/reconcile affected native work, then admit a successor stage. Do not claim a mid-run free-text conversation retargets an executing script. Keep durable acceptance/recovery outside same-session replay. Workflow deterministic control flow does not make its generated contents trusted supervisor code.

Assumption: default to supervisor-owned continuation for admitted obligations. Native goal is optional only with a proven allowed evaluator profile and explicit ownership of continuation. It cannot replace final artifact checks or durable accounting. Do not run two independent retry/continuation owners for the same obligation. Permission waits, user pauses and missing native results remain distinct states.

## Long-horizon operation and proposed validation order

Assumption: native sessions retain conversational reasoning, tool use, memory and adaptive delegation. K persists the accepted objective/method revision, expected population, task/attempt lineage, source/artifact identities, pending requests, observed native sessions/tasks, and unresolved side effects in SQLite plus artifacts. Store concise handoffs as indexes to originals, not substitutes for them. Native compaction is not a reason to discard raw evidence or start every round in a new session.

Assumption: validate these implementation increments with the proposed V command before moving to the next increment:

4. Native capability admission: approved later model probes establish actual Fable/Opus identity, chosen effort, advisor occurrence, subagent/team distinction, Workflow resume/input limits, and real stop behavior. Expected result: unsupported guarantees are explicitly blocked, not silently downgraded.
5. Generated-project delivery: render to a clean temporary project and run its own factory fixtures and asset resolver with no developer-private assets. Expected result: complete factory/contracts/roles/tests available under seed; native mirrors equal; optional features produce explicit capability statuses. Then the single validation owner runs repository `bin/check` for the final snapshot and requires its real `check: PASSED` summary.
