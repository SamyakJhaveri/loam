# Claude Code native adapter: evidence and engineering recommendation

Status: design evidence only. No native model execution, SDK installation, prototype, repository mutation, credential read or activation. This report follows accepted state-design.md and records-and-transitions.md. Model policy remains Fable 5.1 driver, Fable 5.1/Opus 4.8 only for Claude-side model roles, with effort selected by the user. Public documentation is evidence of an interface contract, not proof of installed-host execution.

Critical point: persistent steering must not be mistaken for native cancellation or permission to accept a result from a superseded requirement.

## Recommendation

Recommendation: use the official TypeScript Agent SDK's open-input `query()` as the preferred full programmatic Claude Code adapter. Keep the input iterable alive and consume the output generator continuously. This retains the native agent loop, tools, context, subagents, Workflow, skills, plugins and MCP while giving Loam structured control and observations. The SDK process is an adapter owned by the local supervisor; it does not become a second operational-state authority. Selecting this adapter does not require the supervisor or generated project itself to use TypeScript.

Recommendation: preserve two other explicit routes. The Python `ClaudeSDKClient` is credible where its verified controls satisfy the admitted requirements. One-shot CLI execution remains useful for bounded independent review or extraction. An ordinary interactive Claude Code session remains the route for native agent teams and direct human brainstorming. Do not label these surfaces equivalent. Do not reimplement Claude's model/tool loop through the Messages API or transplant Managed Agents sessions merely to get a uniform facade.

Verified: current streaming documentation describes persistent interactive input, sequential message queueing, image input, interruptions and full tools. Single-message input lacks dynamic queueing and real-time control. The removed TypeScript V2 `createSession` API is not a viable basis. [Streaming input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode), [sessions](https://code.claude.com/docs/en/agent-sdk/sessions).

## Public SDK interfaces and what they establish

Verified: the pinned TypeScript package exports `query({prompt: string | AsyncIterable<SDKUserMessage>, options})`, returning `Query`, an async generator. The following are public methods in its declaration, rather than inferred wire calls. [Published package](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.270.tgz).

| Public interface | Documented meaning | Loam judgment |
|---|---|---|
| Async input plus `streamInput(stream)` | Deliver user messages into the live session | Own one ingress queue and one output consumer. Persist steering before delivering it; do not infer delivery from placing it on Loam's queue |
| `interrupt()` | Interrupt current execution; returns `SDKControlInterruptResponse` or undefined on older CLI | Persist barrier first; preserve receipt and ensuing events. Undefined is an observation gap |
| `stopTask(taskId)` | Request stopping a background task, followed by a stopped task notification | Record task-specific intent and observe both task events and process boundaries; do not equate method return with filesystem quiescence |
| `backgroundTasks(toolUseId?)` | Move foreground Bash/subagent work into background, optionally one identified call | Useful for long experiments while the lead discusses findings. Background is still executing, not paused |
| `close()` | End query, pending requests, transports and CLI subprocess; no further messages received | Last-resort shutdown path. Capture what is available before closure and independently reconcile surviving external work |
| `initializationResult()`, `reinitialize()` | Initial cached handshake or fresh handshake after transport gap | Record observed host identity; replay-safe callbacks. Reinitializing can deny/retry an unanswered hook and is not a free side-effect-free status read |
| `supportedCommands()`, `supportedAgents()`, `mcpServerStatus()` | Available named assets and connection state | Capability inventory only. Names do not prove required content loaded or behavior occurred |
| `setModel()`, `applyFlagSettings()` | Change model/settings in current session | Restrict behind explicit readmission/user authority; never automatic effort optimization. A null/default reset can change the user's selection |
| `spawnClaudeCodeProcess` option | Supported custom spawn with command, args, cwd, env and signal | Credible place for the owning supervisor's process identity and execution boundary. OS/process guarantees still require testing |

Verified: public `Query.interrupt()` has no options argument and no public `cancelAsyncMessage` method appears in the complete Query declaration. The same package contains a non-exported wire request type with `cancel_queued?: boolean` and a capability named `interrupt_cancel_queued_v1`. That is not a callable public `Query.interrupt({cancelQueued:true})` API. Do not implement against SDK private objects or untyped wire access while presenting it as supported SDK behavior.

Recommendation: prefer supported SDK methods now. A future direct bidirectional CLI protocol adapter is credible only after its exact public transport contract, cancellation request path and event delivery semantics are separately established and tested. Merely knowing a wire field exists does not complete that adapter. Retain raw unknown events in the archive even when a projection does not understand them; unknown events cannot satisfy required evidence.

## Steering, stale queues and safe continuation

Verified: `SDKUserMessage` supports caller UUID, provenance `origin`, optional priority and `shouldQuery`. The comments require a genuine human-input wrapper to stamp `origin: {kind: 'human'}`; absent origin is unattributed at strict human gates. Peer routing identity is sender-asserted; even a verified peer PID identifies the connecting process and is recyclable. [Published input/provenance types](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.270.tgz).

Recommendation: preserve genuine authenticated user messages with their original source identity. Never stamp generated repair prompts, source text, queued experiment notifications or another agent's message as human merely to unlock Workflow or other human-origin features. A user-authorized programmatic task still needs an honest distinction between that authorization and later model-authored instructions. Native provenance complements Loam's authenticated ingress; it does not replace it.

Recommendation: record separate facts: steering persisted; delivery attempted; transport accepted where observable; native queued; native consumption observed; current method/profile application validated. Correlate caller UUIDs to native `user_message_uuid` and `user_message_uuids`; one turn may consume several inputs. Correlation proves which messages a turn consumed, not that the model correctly obeyed the changed requirement. Missing correlation remains unknown. Do not resend after lost acknowledgment unless reconciliation establishes whether the message was already consumed.

Verified: the interrupt receipt's `still_queued` covers UUID-stamped main-thread messages, not all possible work. Queued batches can already be coalesced. UUID-less notifications and descendant-addressed messages fall outside that list, and internally generated UUIDs can appear. `queued_turn_count` likewise excludes system queue entries. Thus empty lists do not prove global inactivity. The receipt is a snapshot at abort processing; querying after the result can lose the race to the next queued turn. These are explicit pinned-package comments, not hypothetical objections.

Recommendation: Loam retains pending consequential steering in its durable ingress until admitted for native delivery, rather than preloading a backlog of incompatible objectives. User conversation remains asynchronous. Informational messages may be delivered while work runs, but a change in method/profile installs a barrier before classification. A plain pause must stop affected future dispatch/acceptance/publication even if native interruption is delayed.

Recommendation: if already delivered stale messages cannot be recalled through the chosen public surface, report that fact and keep the run blocked. Interrupt the current turn; stop affected native tasks; close the session if necessary; reconcile old processes, task handles, artifacts and side effects before any conflicting successor launch. Do not claim queue cancellation from `close()` or blindly resume the old session. Resume can continue an unfinished old turn. When the transcript cannot be established compatible, start a new native session with the accepted revision and validated evidence. This is a recovery choice for unresolved stale input, not a policy of resetting context every round.

Verified: sessions persist conversation, not files. Explicit `resume: sessionId` targets a known session; `continue: true` picks the latest session in the directory. Fork duplicates conversation but shares the filesystem unless the caller isolates it. Recommendation: use explicit IDs, separate workspace ownership and successor lineage. Never use latest-session discovery to bind a factory attempt. [Sessions](https://code.claude.com/docs/en/agent-sdk/sessions).

## Foreground, background and truthful stop controls

Verified: `perTaskStopAffordance` declares a real consumer control wired to per-task stopping. In an open-input session it makes interrupt spare background agents/workflows; closed-input one-shot runs retain different shutdown behavior. The declaration is first-attached-client sensitive. `background_tasks_changed` is a per-process replacement snapshot; its event ordering relative to task bookends is unspecified. Reinitializing an existing process can provide a fresh snapshot. [Published task/control types](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.270.tgz).

Recommendation: expose “interrupt this conversation turn,” “stop this experiment/helper,” and “pause this admitted work” as distinct actions where the user-facing surface supports them. Set the affordance only when the user can actually stop every displayed task through the trusted control path. A whole-work pause must explicitly include affected background work. Do not hide an unresolved writer because a task is labeled ambient or because the foreground result arrived. Native task snapshots inform reconciliation; they are not an inventory of every remote job or escaped process.

Verified: one-shot headless execution has background exit/wait rules. SIGTERM leaves an unfinished turn without a result, terminates running Bash process trees and later resume continues that unfinished turn. SDK close can cancel pending prompts as stdin closes. Recommendation: distinguish interrupted, denied, capped, missing-result and process-ended observations; never treat absent final output as an empty successful artifact. [Programmatic CLI lifecycle](https://code.claude.com/docs/en/headless).

## Permissions and waiting for the user

Verified: `canUseTool` receives native request identity, tool-use identity, optional agent identity and cancellation signal in the pinned TypeScript type. It is not invoked for all tools: permission rules/modes can resolve a request first. `allowedTools` pre-approves rather than restricting the complete tool set. `plan` still allows analysis and routes writes for approval; it is not total tool disablement. Use the current permission guide over misleading abbreviated type comments. [Permission evaluation](https://code.claude.com/docs/en/agent-sdk/permissions).

Recommendation: bind each approval/question to native request ID, Loam attempt, expected revision and exact requested action digest. Surface a real pending request through the user's chosen interface; a duplicate delivery shows the same request. Resolve only after checking its barrier and revision. A stale answer is recorded but cannot approve a changed tool call. Cancellation signals close the pending UI while preserving its history. Do not persist an “always allow” rule incidentally from a one-time answer.

Verified: `AskUserQuestion` travels through the callback; original questions and answers return in `updatedInput`. General freeform responses are supported. The tool is unavailable inside Agent subagents. Recommendation: research helpers report consequential questions to their native lead, which asks the user without inventing a reply. The user can also steer without waiting for the agent to ask. [Approval and question guide](https://code.claude.com/docs/en/agent-sdk/user-input).

Verified: a synchronous SDK PreToolUse callback can check every tool call, including descendant calls; its timeout blocks that call. Command/HTTP hook timeout does not provide the same gate. PreToolUse does not cover prompt `@` file expansion or EndConversation. Async hook output cannot block. Recommendation: use synchronous callbacks for the admitted barrier on covered calls, OS/data boundaries for state protection, and retain independent acceptance authority. [SDK hooks](https://code.claude.com/docs/en/agent-sdk/hooks), [hook coverage](https://code.claude.com/docs/en/hooks).

Verified: `defer` preserves a pending tool for later resume only in print/SDK mode and only for a single tool call in that turn. A batch causes defer to be ignored and normal permissions to proceed. Transcript retention still applies. Recommendation: useful for long waits when the actual returned deferred receipt establishes it; not a general reliable pause gate. If a batch cannot be deferred, an ordinary pending callback or explicit denial/interruption remains necessary. [Deferred tool contract](https://code.claude.com/docs/en/hooks#defer-a-tool-call-for-later).

## Preserve research and engineering capabilities

Verified: SDK defaults and explicit setting sources affect instructions, skills, agents and hooks; managed policy, global configuration, auto memory and claude.ai connectors have separate behavior. `strictMcpConfig` can suppress connectors. Skills remain filesystem assets. Recommendation: resolve and validate the admitted project/native profile; avoid `--bare`, empty settings or blanket strict MCP as shortcuts that silently remove required research tools. Preserve intended native context and memory, while binding accepted lessons to evidence in Loam's separate records. [Native features in SDK](https://code.claude.com/docs/en/agent-sdk/claude-code-features).

Verified: SDK subagents support exact model and effort overrides, role prompts, tools, skill preloads and background execution. Named helpers with SendMessage can know their peers. Native agent teams still require interactive sessions; SDK sessions do not spawn teammates even if teams are enabled. [SDK delegation](https://code.claude.com/docs/en/agent-sdk/subagents), [native teams](https://code.claude.com/docs/en/agent-teams).

Recommendation: provide inquiry roles for source acquisition, method design, rival hypotheses, experiment execution, replication and synthesis. Let the Fable driver delegate and revise plans through native mechanisms. Give experiment roles the actual approved data/tools and isolated writable workspace; a read-only evidence reviewer cannot reproduce an experiment merely by reading logs. Preserve original outputs and claim/source identities across handbacks. A null Workflow result or absent specialist stays an unmet obligation.

Recommendation: use the interactive native team route when the requested deliberation requires teammates' independent sessions and direct human addressing. Record its admitted stage, artifacts, decision handoff and observable lifecycle without pretending that a TUI transcript is the SDK event protocol. If unattended completion requires guarantees unavailable from that route, expose the gap instead of silently substituting a solo agent. Ordinary exploratory discussion need not become a ticket before the user can think with the lead.

Source roots from previous complete original reads: S14's research system motivates parallel evidence gathering, adaptive strategy and artifact references; S12 motivates continuity and calibrated independent evaluation without mandatory session resets; S13 motivates durable history separate from replaceable execution; S38/E-WORKFLOWS provide native schema-bearing workflows and same-session replay; S36/S37 provide bounded specialist handbacks and separate outcome evaluation. Engineering judgment adds protected immutable evidence, typed missing/error results, current required-population coverage and explicit user-steering barriers. These additions are Loam's design, not claims that the source examples already guarantee them.

## Model, effort and accounting evidence

Recommendation: bind top-level `model` to the exact resolved Fable 5.1 identifier and `effort` to the user's selection. Resolve role definitions to Fable 5.1 or Opus 4.8 only. Inspect effective model/tool/skill/plugin observations and current-turn hook effort where available. Explicit role configuration is stronger than an alias or instruction, but does not establish every hidden helper invocation. Optional advisor, goal evaluator and model-based hooks need their own admissible identity evidence. If a required effective setting is absent or overridden, block the dependent guarantee rather than changing effort or accepting a disallowed fallback.

Verified: the pinned init type's effective `effort` field is documented for some bridge surfaces, not universally all SDK hosts. Per-tool hook effort can expose current effective effort. Init model and result `modelUsage` provide useful but incomplete observations. `modelUsage` covers query-pipeline calls including subagents/Workflow/compaction, but excludes helpers outside that pipeline, such as a permission classifier. These boundaries prevent an absolute hidden-call compliance claim.

Verified: streaming results report cumulative `total_cost_usd` and `modelUsage` for the query; summing each result would duplicate usage. Main `usage` is per-turn and excludes helper calls. Resume and clear can reset query counters, while crash results may be zeroed. Recommendation: retain raw counters, identify query/accounting epochs, derive deltas only with compatible identities and preserve unknown usage. Do not reset the accepted accounting scope on resume or successor work. These records are for truthful execution accounting, not a reason to reduce user-selected capability. [Published result and init types](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.270.tgz).

## Existing factory and precise proposed change

Verified: bin/factory:842–849 launches `claude -p` with a finite stdin prompt, streaming output, bypassPermissions, strict MCP and user-only settings. It parses only the last result after the call, while retries repeat the invocation. This preserves a useful native execution foundation but provides no live ingress, pending-request host, durable delivery correlation or explicit session resume in that worker call.

Recommendation: replace the worker transport behind the accepted dispatch/observation interface. Retain native generation, frozen task inputs, artifacts and independent checks. Add structured ingress, continuous observation, permission UI, per-task controls and actual native identity receipts. A round is not a session by definition. A result is a native turn outcome, not Loam acceptance. Keep direct CLI one-shot for obligations whose declared semantics fit it, with explicit narrower capability admission.

## Later acceptance scenarios, not executed tests

- User submits a method change while the prior turn and a background experiment are active. The barrier commits first. The UI shows persisted, delivered, consumed and applied states separately. The old result cannot satisfy the successor method.
- Queue multiple user messages, interrupt before startup and between tool rounds, then receive coalesced replies. Correlate every supported UUID; do not infer a one-to-one message/turn mapping. An absent receipt or unrecallable old message keeps the relevant continuation blocked.
- Pause whole work after foreground completion but before the background task exits. Further acceptance stays blocked; per-task stop remains available; unrelated permitted work continues.
- Lose the response to an approval and reconnect. A duplicate native request appears once; the same durable decision is replayed only if current revision and action digest still match. A cancelled or changed request rejects the stale answer.
- Defer a single question, then a parallel tool batch. Only a real deferred receipt permits exit-and-resume behavior; the batch cannot slip through a pause because the implementation assumed defer always blocks.
- Crash after native dispatch but before session capture. Reconcile the unknown launch rather than launching another writer. Close/restart/resume cannot bypass old task and external-effect reconciliation.
- Run source acquisition, a live computation and independent evidence review with actual domain tools. Verify claim coverage and method outcome separately from process success; an inconclusive experiment is a valid conclusion where admitted, not an execution error.
- Compare requested and observed role models/effort, capability inventory and required skills in generated projects. Exercise disallowed fallback, missing effective effort and hidden-helper evidence gaps without silently changing the user's profile.
- Feed cumulative streaming usage, a resume reset, a clear event and a zeroed crash result. Preserve totals once and unknown amounts explicitly.

## Self-attack and limits

The largest unresolved boundary is stale native input already delivered into a queue the public SDK cannot purge. This report retains that uncertainty and requires reconciliation before conflicting work. The next is native descendants or external experiments outliving the lead; task observations are necessary but not sufficient OS proof. Full effective-model observability is also incomplete. No runtime compatibility, crash safety, OS isolation, paid model behavior or outcome improvement was tested.

The current docs and published types disagree in a few summaries: the permission guide establishes plan-mode analysis despite abbreviated type comments saying no tools; the general headless stream paragraph calls result the last line while precise result types allow informational events afterward. Use specific current contracts and preserve continuous draining. TypeScript's public return type does not expose every pending-request field described by wire comments; use supported callback replay rather than assuming undeclared fields are stable.

Next step: implement the accepted mechanical fixtures with a fake native adapter only after implementation authorization, then run separately authorized bounded native probes against an explicitly admitted SDK/CLI pair. The proposed transport remains native and capable; guarantees grow only with evidence.
