## Acceptance
- Runtime-validate work, attempt, candidate/criterion/required-population identity, actor authorization and artifact records. A native turn/process exit/check finish/accepted work are distinct. Bound fake execution is labeled; it grants no actual lead authority.
- Persist dispatch authorization and host bootstrap identity before dispatch. Stable host lock/ledger prevents duplicate bootstrap; host is an execution observer, cannot change models/obligations, write project acceptance or independently retry.
- Protected check host owns candidate output capture. Bounded integrity-checked frames preserve original bytes, host/stream identity and ordered positions. Publish complete immutable artifact before authority receipt; transact ingestion cursor, observation and settlement together. Same frame replay is idempotent; identical text in different frames is distinct.
- Missing checks, invalid/partial result, changed candidate/criteria, stale revision, new obligation, repeated confirmed blocker or repair cap cannot become acceptance. Preserve inquiry-only outcomes. S2 establishes durable loop outcomes; S3 adds native dynamic child accounting and independent review integrations.
- Future focused command after build: `node --test seed/.loam/factory/dist/tests/execution/local-recovery.test.js`. Assert nonempty bounded task/check path, invalid authority/revision rejection, output larger than queue capacity with reader responsiveness, partial/oversized/corrupt/gapped/exhausted spool blocking satisfaction, and artifact-before-receipt crash cases. Status shows original task/attempt and captured evidence; candidate cannot forge authoritative receipt. Both host mechanics apply.
