# CORE-05: Open and retain sole authority over an existing registered store

Stage: S2

Recommended implementation lead: Codex/Astra

## Blocked by

[CORE-04: Admit an isolated installed runtime from an independent trust source](03-core-04.md)

## What it delivers
A protected scratch supervisor opens an already initialized store, owns it for its process lifetime and rejects conflicting or invalid authority. The existing Bash controller has no dedicated SQLite owner; its file state cannot satisfy this contract. Fixture initialization is explicit creation, never recovery fallback.

## Canonical source changes
Create `seed/.loam/factory/src/store/worker.ts`, `src/store/transactions.ts`, `src/store/migrations.ts`, `src/supervisor/owner.ts`, `tests/store/ownership-recovery.test.ts`, and the initial versioned schema under `migrations/`; extend `src/contracts/installation.ts` and `src/platform/ownership.ts`. The dedicated creation entrypoint is reserved for fixture initialization and CORE-06 pending setup. Define typed/versioned authority commands before callers.

## Read before planning
`first-run-ownership-storage-recovery.md`: Starting and retaining the sole owner, crash/conflict table. `engine-runtime-and-layout.md`: Runtime and storage baseline. `prior-design/state-design.md` and `prior-design/records-and-transitions.md`: transaction/authority and identity contracts. Read current `bin/factory` state/resume callers repository-wide before reusing concepts.

Initial explicit creation is allowed here; non-initial migration requires protected maintenance authority and must remain unavailable until CORE-09 external-marker machinery exists. Later memory/improvement schemas consume this versioned contract; they do not invent a second migrator.

## Acceptance
- Supervisor holds stable existing lifetime lock, store worker owns SQLite connection. Never unlink/replace lock; verify locked-object identity; no child inheritance or timeout/PID takeover.
- Existing-only internally encoded local URI with fixed mode refuses missing, empty, corrupt, foreign and incompatible stores before application mutation. Test hostile path characters and precheck/open deletion; missing file stays absent. Reject arbitrary/in-memory/remote URI and create fallback.
- Validate instance/schema under lock; record fresh random owner incarnation and publish rendezvous only after authority commit. Restored database cannot repeat an owner identity. Read back effective foreign keys, journaling/sync and integer behavior qualified in CORE-02.
- Typed domain transaction checks owner, actor scope, current revision and barriers, committing event/state/settlement together. Worker-provided arbitrary SQL is refused. Busy SQLite does not block the event reader.
- Store-thread death closes admission/dispatch, retains process lock through reconciliation/shutdown, and never swaps in a writer. Startup gaps are unavailable/reconciling; already authorized actions stay in-flight.
- Future focused command after build: `node --test seed/.loam/factory/dist/tests/store/ownership-recovery.test.js`. Run fixed admitted scratch fixtures on both hosts. Negative fixtures above fail intentionally without repair; corrected implementation shows exactly one owner, preserved absent store, responsive capture and atomic typed transaction outcomes with explicit counts.

## Exclusions
No ordinary new-instance setup/registration flow, host execution, takeover by stale heartbeat, in-memory fallback or automatic foreign-store repair. Full store recipient group remains incomplete.
