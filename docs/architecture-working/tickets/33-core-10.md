# CORE-10: Preserve user control and effort limits across work revisions

Stage: S2

Recommended implementation lead: Codex/Astra

## Blocked by

[CORE-07: Record a bounded task and durably capture its deterministic check](07-core-07.md)

## What it delivers

A user can pause, resume, cancel, answer or revise a bounded task while it is running. The factory preserves the right execution barriers, predecessor history and the same effort allowance. Current root stop-marker and per-round settings do not implement this typed shared-scope contract. This slice follows the first bounded task/check path and precedes crash recovery and native integration.

## Acceptance

- Authenticate steering ingress; source/report text and a model classification cannot impersonate the user. Persist request identity, actor, expected revision, payload digest and durable order, installing the affected barrier before classification. Duplicate same-body requests replay; conflicting identity reuse fails.
- Each request owns an individual barrier. Resume or informational classification resolves only explicitly named barriers at the expected revision. Resume cannot undo cancellation or supersession and cannot remove a newer revision or unrelated pause. Plain stop pauses future authority and requests interruption; display unresolved physical work separately.
- A requirement/profile change creates immutable successor inputs/run and preserves original evidence/finding lineage and accounting scope. Reconcile old writers before conflicting new execution. A stale answer cannot satisfy a successor request. Scope-limited steering leaves proven unrelated work eligible.
- Dispatch ordered before a stop may be in flight; stop ordered first prevents it. Pause/cancel blocks affected acceptance/publication but still permits capture and actual usage settlement. An interruption acknowledgment never proves every descendant stopped.
- Bind every descendant, retry, resumed invocation and successor run to one effort accounting scope unless an authorized adjustment explicitly changes it. Reserve before dispatch and retain unresolved reservations. Unknown usage is not zero. Preserve cumulative/interval/parent-child aggregation provenance and counter epochs, so overlapping totals and a reset provider counter do not double-charge or create a fresh allowance.
- Distinguish elapsed deadline, defined active-time intervals and actual model/resource usage. Pausing does not extend an elapsed deadline without explicit adjustment; active intervals carry across restarts. No model/effort change is implied. If exact cap enforcement is unsupported, the dependent profile must expose that limitation rather than certify it.
- Future commands, unimplemented and unrun: after build, `node --test seed/.loam/factory/dist/tests/supervisor/steering.test.js seed/.loam/factory/dist/tests/store/accounting.test.js`. Nonempty negative cases cover pause during valid completion, cancel plus late success, stop before/after dispatch, requirement change during checking, duplicate/conflicting steering, stale answers, resume versus newer revision and informational classification versus another pause. Accounting cases cover retries/descendants/successors/native-shaped resume, overlapping parent/child totals, counter reset, unknown amounts, unresolved reservations and elapsed/active time.
- Positive evidence: authorized resume of the unchanged paused run resolves only its named barrier; an authorized revised task preserves old history and remaining allowance; capture and replay settle original usage once without granting new work. Both hosts exercise the same deterministic cases. Native ingress/usage observations are connected and separately proven in NATIVE-03/04, with required child scope binding in NATIVE-02. CORE-08 repeats these guarantees through actual host/supervisor recovery.
