## What to build

Verified current behavior: `memory-loop-engineering.md` explicitly requires evaluation throughout real project work after installation; `first-complete-slice.md` says a demonstration cannot establish general usefulness. Produce the first bounded, evidence-linked real-use report using the installed factory on authorized project tasks. This is an evaluation task with narrowly scoped instrumentation repairs only, not a new memory subsystem or recurring automation.

Record useful retrieval, harmful carryover, missed retrieval/corrections and task outcomes with exact displayed output, record, context-packet and run identities. Record absent or inaccessible evidence as missing. Keep feedback attached to the actual output the user saw. Separate observed association from causal claims. Use observations to create a scoped diagnosis and, where justified, a fixed baseline/candidate comparison with equivalent starting memory, isolated arms, unchanged selected models/effort, declared criteria and all required cases retained. Broad generalization requires an appropriate declared repeat-trial/held-out design; otherwise report a bounded repair or inconclusive evidence.

If real use reveals harmful advice, correct/block affected use promptly without waiting for a better replacement. Preserve evidence and history. Lead-owned adoption remains separate: no evaluator score adopts an improvement, and no lead means pending. Results and adaptations remain project-local; exporting private traces or shared Loam promotion is separate work. Do not force a favorable research answer or improvement outcome to pass this ticket.
