# OPS-07: Fence the old controller before moving ownership to a replacement machine

Stage: S5

Recommended implementation lead: Codex/Astra

## Blocked by

[OPS-04: Enforce mixed offline behavior at each job host with a simple personal queue](25-ops-04.md), [OPS-06: Restore remote history without reopening retired requests or withdrawn memory](27-ops-06.md)

Legacy obligation mapping: MAINT-02 replacement-machine enrollment and owner fencing.

## What to build

Verified current behavior: the design names replacement Mac/Linux enrollment but current source has no proposed runner authority-transfer operation. Move a project to a replacement Mac using consistent protected state and a separately authenticated operator-authorized rebind. A generic client cannot claim a larger generation to acquire work. If old authority is unavailable, preserve unresolved work and use explicit reconciliation rather than automatic failover.

Fence project enrollment on every runner, not only known job IDs. Serialize the transfer with admission and final dispatch. Validate current generation on every mutation, including entirely fresh submits, queued dispatch, lease renewal, approvals and cancellation. Reconcile work admitted by the prior owner. Until an unreachable target acknowledges fencing, keep it pending rebind, deny new dispatch there and do not claim exclusive new ownership. The old controller must fail with an entirely new request identity after transfer.

Enroll replacement Linux hardware with a new machine/runner identity and fresh readiness. A familiar SSH alias cannot collect, cancel or rerun old-machine jobs. Preserve old jobs' last observed state/artifacts; lost hardware does not settle unknown execution or inherit live capabilities.
