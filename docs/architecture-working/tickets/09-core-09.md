# CORE-09: Back up and restore local history through a durable external barrier

Stage: S2

Recommended implementation lead: Codex/Astra

## Blocked by

[CORE-08: Reconnect to the original host and settle captured results once](08-core-08.md)

## What it delivers
An operator can take a consistent quiescent scratch backup and explicitly restore it through crashes without reopening ordinary authority on uncertain history. Current factory has no transactional SQLite/artifact backup or protected external restore marker. S5 extends this local primitive to remote jobs/upgrades rather than deferring restoration safety.

This ticket also implements the guarded local non-initial migration primitive consumed by subsequent schema tickets: under retained lifetime/registry ownership, prove quiescence, create a verified backup, persist the external pending migration marker, invoke CORE-05 versioned migration runner, validate the resulting schema/history, and clear the marker only after durable completion/reconciliation. Crash injection before/after application retains the marker and old evidence; the old incompatible runtime refuses the migrated store. This is local schema migration safety, not S5 controller/runner update orchestration. Memory and improvement migrations may apply to existing registered stores after this ticket, through this primitive only.

## Acceptance
- Quiesce host/spool mutation and close DB connection while supervisor retains lifetime ownership. Copy DB, all referenced immutable artifacts and registration/host inventory to verified durable manifest; publish backup completion last. Reopen/validate under same owner before normal work. Unprovable quiescence blocks backup completion.
- Explicit restore preserves current records/backups, compares protected host inventory and external effects, and holds registry/instance ownership. Never swap files while old readers/writers depend on them. Imported evidence grants no execution authority; possible surviving remote execution leaves evidence-only state until later coordinated transfer.
- Before DB replacement, durably publish external pending transaction with old history identity, selected backup digest, staged replacement identity and unresolved-history barrier. Stage/validate replacement with fresh history identity and installed barrier, publish durably, and resume the exact transaction after crash. Every startup checks external marker before ordinary recovery. Do not restore old control capabilities or repeat owner incarnation.
- Clear marker only after replacement identity and required reconciliation are durable; unresolved uncertainty retains marker/barrier. Lost correction/adoption/authority history cannot reactivate memory or old lead decisions; require reconciliation or user-established current baseline. Historical external effects are preserved, never treated as undone.
- Apply the same external-marker admission discipline to interrupted migration visibility without implementing S5 upgrade orchestration. Compatible version text alone cannot bypass pending maintenance.
- Future focused command after build: `node --test seed/.loam/factory/dist/tests/store/ownership-recovery.test.js`. Crash before/after marker durability, staging/barrier identity, replacement publication and completion; test newer host absent from backup, artifact loss, incompatible store and lost correction history. Each restart stays in named reconciliation until valid; successful reconciled restore exposes new history/owner and retains old evidence. Run both hosts.
