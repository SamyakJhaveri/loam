# Loam Factory: harness bets

The register the design rule in `ARCHITECTURE.md` asks for: every harness component is a dated bet on a model weakness and must justify its keep after each upgrade.
One row per component: since when it exists, the weakness it covers, the replay that would retire it, and the pull request (`#n`) that added it.
Since is the date of the commit that added the component; Added by is the pull request that merged that commit, or the issue that asked for it when the commit reached `main` without one.
Only the worker advisor has an off switch; for every other row, remove the component on a scratch branch, never on `main`, and run the replay there.
A grader replay follows `LOOP.md`, Grader change protocol, from a scratch worktree as `evals/planted/CASES.md` shows, since the checkout holds the answer key.
After a model upgrade, replay one row at a time; a row whose retire result holds is removed in its own ticket, and its row goes with it.
