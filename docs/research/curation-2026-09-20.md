## Verdict in five lines

Loam today has no memory of any kind, no Learn stage in code, no runnable method through its runtime, and no place for a project to add its own check; those four facts, not the outside documents, set the picks.
The four repos hold nothing to adopt as a dependency; two small mechanisms are worth a few lines each, one from loop-engineering and one from LongHorizon.
The Reddit thread's advice is already Loam's spine; two of its gaps are cheap and real.
The setup file serves a non-programmer with a hosted deploy path, which Loam does not; one of its habits, prove the connection before moving on, applies to `_gh_setup.sh`.
The memory design's evidence is sound, all 15 findings verified, and it overlaps the accepted design more than it contradicts it; the difference is order and one mechanism, and the cheap half should be built and measured before NATIVE-09.

### AMAP-ML/LongHorizon-Harness

MIT, v0.1.7, 1606 stars, last push 2026-08-20.
Drives agent CLIs as subprocesses; seven roles; per-role model and effort resolve down a parent chain (`cli.py:2020-2074`) but default to one model for every role.
Completion is regex over a `Next:` line and a three-line auditor header (`role_prompts.py:481-499`, `auditor_agent.py:23-36`).
Every role runs `--dangerously-skip-permissions` (`claude_permissions.py:33-72`); the docstring says the deny list is role separation, not a sandbox.
Caps: rounds and per-episode wall clock only; no token, dollar, or total-time cap.
A human gate fires at the end of every round through the dashboard (`gate.py:48-103`); headless, `ask` stops the run.
No memory across runs; auto-memory is disabled (`claude_code.py:59`).
The README benchmarks ship repro code but not the datasets.

Two things worth taking, both small and rule-clean:

- The auditor snapshot-and-diff guard (`claude_permissions.py:105-198`, `claude_code.py:137-184`): hash the workspace before and after the auditor, and invalidate the audit if it changed. Loam's graders have no write tool at all, so the risk is a tool-list regression, not a design gap. Five lines in `graders()`: record `HEAD` and `git status --porcelain` before the judge and after the last grader; a difference exits `stopped-environment`.
- The acceptance-constraint back-check (`prompt_texts.py:225-260`): the auditor must reconstruct the acceptance constraints from the task itself and challenge each one; its own report and the executor's claims are not evidence. Loam's judge already scores `correct` against the ticket; the sentence worth adding to `judge.md` is "re-derive the ask from the Goal section alone before reading the diff", which is the same rule autoprompt reached.

### Forward-Future/loopy

A Cloudflare Worker catalog site plus one skill; no code calls a model.
The skill defines a loop as observe, choose, act, verify, record, repeat or stop (`SKILL.md:200-235`), six terminal states, a mandatory silent preflight, and a run receipt returned in conversation.

### ray-r-ren/agent-apprenticeship

MIT, 1617 stars, last push 2026-07-06; typer, pydantic, openai.
A real pipeline: an external coding CLI is the apprentice, an HTTP model is the mentor.
The loop is hard-capped at two attempts (`loop.py:58-210`); `max_iterations` above 1 is dead.
Per-role model overrides apply only when the provider is OpenAI (`grader.py:150`, `verifier.py:46`, `evaluator.py:159`).
The Claude apprentice runs `bypassPermissions` with no envelope (`apprentice_adapters.py:122-124`); expert mode parses approval words from free text (`mentor_checkpoints.py:111-192`).

Its rubric returns a numeric score and a reliability stamp, not a severity-bound verdict word (`grader.py:174-194`), which matches Loam's F23 lesson.
Nothing to take.

## The memory design, verified and placed

### Its sources hold

All 15 findings resolve to real papers whose titles match; every load-bearing number (findings 1, 6, 7, 8, 11, 15) matches its source.
Six scope slips, none reversing a direction: finding 2's Mem0 parity holds on 2 of 6 question types only; finding 10 says +16.2pp where the paper says +16.6pp and the +4.5pp software-engineering figure is in no abstract; finding 12's "LoCoMo only" is unconfirmed; finding 14's reproducer is a competing vendor and the "25 points" span is not quantified; findings 3 and 4 carry framing not in the abstract.
Every section 2 fact about Claude Code and Codex is current: `autoMemoryDirectory`, `cleanupPeriodDays`, `.claude/rules/*.md` with `paths:`, the 200-line `MEMORY.md` load, SessionStart `additionalContext`, Codex `[features] memories` and `~/.codex/memories`, Codex hooks with the same event names.
The capture script's reliance on `transcript_path` at SessionEnd, PreCompact, and Stop holds on Claude Code 2.1.267, with one caveat: the transcript is written asynchronously and the Stop capture may miss the last turn's messages.

### The two designs side by side

The accepted design lives in `docs/archive/architecture-working/memory-loop-engineering.md`, `memory-records-and-delivery.md`, and `decision-delta.md:15-18`; the tickets are NATIVE-09 (#120), NATIVE-10 (#121), NATIVE-11 (#123), OPS-11 (#137), all open, unassigned, unlabeled, at stages S3 and S7.

Where they agree:

- Retrieval is deterministic constraints first, then ordinary lexical search; embeddings and graphs wait for measured misses (P-MEM-RETRIEVE; the design's levels 2 and 3).
- Bodies live in files; the accepted design holds only identity and lifecycle in SQLite.
- Raw transcripts are never auto-promoted (`memory-records-and-delivery.md:15`; the design's human-gated ladder).
- Governing decisions, permissions, models, and acceptance never become writable memory (both).
- A relevant stale lesson must not outrank a correction (P-MEM-CORRECT; the applicability gate).

Where they differ:

| Question | Accepted design | The 2026-09-03 design | What the evidence says |
|---|---|---|---|
| Who activates an ordinary lesson | a model, under policy, "no human approval for every note" (`memory-loop-engineering.md:45`) | a human, at a weekly report, on recurrence | finding 1: a bank a model keeps rewriting rises then falls below no memory; finding 6: consolidation contributed nothing; the accepted design's consolidator (`:61`) is exactly the rewriting step |
| Where lifecycle lives | SQLite, "extends the accepted store architecture without a second authority" | git-tracked files under `~/memstore`, one shell script per lifecycle event | finding 6: files win where memory is small, human-owned, and secondary, and files abstain better |
| When to measure | OPS-11 at S7, after S3 through S6 build the store | the complexity ladder: advance a level only on a named, measured failure | finding 7: a frontier actor gains about zero task success from an experience bank; finding 8: cheap trajectory notes are the highest-return step |
| Evidence cited | two vendor cookbooks, four notebooks, two Anthropic articles, loopy's debrief, apprenticeship's verifier | 35 sources, 15 verified findings | the accepted docs cite nothing on whether rewritten memory degrades; that gap is real |

What the accepted design has that the 2026-09-03 design lacks: cross-provider identity for a lesson, an explicit correction that propagates, and a typed proposal envelope that a worker cannot use to grant itself authority.
Those matter once memory is delivered to unattended workers.
They do not matter before anyone has measured whether a Loam worker benefits from memory at all.

### The judgment

This is not a contradiction to resolve by picking a side.
It is an ordering error.
The campaign builds the expensive half (SQLite records, model assessment, delivery, correction: NATIVE-09 through NATIVE-11) before the measurement (OPS-11), on a runtime that today delivers no method and holds no data.
The 2026-09-03 design's levels 1 and 2 cost about 120 lines of shell and zero model calls, and its own finding 7 predicts the measurement may come back near zero for a Fable or Opus worker.
Build the cheap half, run the measurement, and let the result decide whether NATIVE-09's store is earned.
If the ledger shows recurring errors that a card would have prevented, the SQLite lifecycle store has its named failure and the campaign proceeds; if not, NATIVE-09 through NATIVE-11 are cut and the design law "burden of proof is on keeping" is honored.
