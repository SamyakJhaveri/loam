# Cookbook-grounded native connection and agent workflow design

Status: source-audited and cross-critiqued design baseline for the native connection and agent-workflow layer. This finalizes the recommendation at the architecture level, not runtime guarantees or approval of every recipe. Exact protocol compatibility, configuration isolation and native behavior still require the named prototypes. Runtime implementation remains deferred. Accepted user decisions stay in decisions.md; new mechanism choices remain labeled recommendations.

## Architecture recommendation

Recommendation: maintain one portable work contract and evidence authority in Loam, with provider-native execution bridges and a shipped catalog of work methods. A work method is a reusable description of how to investigate, implement or evaluate a class of objective. It specifies inputs, deliverables, dependencies and required capabilities, not every thought or tool call.

The native lead owns its reasoning, tools, delegation and context management. Loam owns admitted scope, project policy, durable records, current evidence, authorization and acceptance. Domain methods determine what counts as substantive evidence. The supervisor does not decide a scientific conclusion by counting model votes.

Recommendation: distinguish these operating surfaces explicitly:

| Surface | Connection and responsibility | Admission boundary |
|---|---|---|
| Ordinary native conversation | Shared shipped entry skills preserve the user's idea and help formulate inquiry, decision, experiment or ticket | Not every conversation is an autonomous factory run. Import an explicit context packet, not an assumed private conversation history. |
| Managed native execution | Owned Codex app-server or Claude open-input Agent SDK bridge consumes an admitted attempt and records native observations | Required control/configuration/observation capabilities must be established for the selected host. No silent CLI fallback after an uncertain launch. |
| Interactive native collaboration | Use real native teams when peer dialogue, direct human interaction or that coordination surface is needed | Preserve the actual team experience. A session ID or transcript alone does not establish lifecycle ownership. Required factory guarantees stay fixed by the admitted work. Use this surface for supervised work only when it satisfies them; otherwise retain ordinary native collaboration with explicit evidence import. Do not call headless subagents teammates. |
| Native batch execution | Explicit narrower exec/print profile for compatible bounded stages | Suitable for stages that do not require an unavailable live channel. No second generic model/tool loop. |

Recommendation: direct human addressing of a teammate must enter the same authenticated steering/approval history when the team performs supervised work. Descendant lifecycle and required model/effort controls must also satisfy that work's contract. If these cannot be established, the team remains ordinary native collaboration. Its outputs can be captured and explicitly adopted as evidence with original lineage and validation, but its transcript cannot grant managed acceptance authority.

Recommendation: use a typed local control boundary between native bridges and the owning supervisor. The names below are proposed Loam responsibilities, not existing commands or provider APIs. Trusted user ingress records questions, approvals and steering. Worker-facing operations submit artifact references, report progress and propose additional obligations. Workers cannot write SQLite authority, approve their own permission expansion or accept their result. Any future CLI/MCP presentation is a client of this same boundary, not a separate scheduler or database writer. Its transport and authorization implementation still need a bounded prototype.

## Choosing the work method

Recommendation: avoid a fixed ritual that runs every technique on every request. The lead chooses a method with a reason tied to uncertainty, independence, dependencies, evidence needs and required native capabilities. The factory records the choice. User model and effort selections remain authoritative; method selection is not permission to downgrade them.

- Direct work fits a sufficiently understood bounded change.
- Inquiry fits uncertainty about facts, mechanisms, competing solutions or feasibility.
- Independent research followed by critique fits substantial questions with separable evidence paths.
- Parallel implementation fits separable changes with clear workspace ownership and integration checks.
- Dynamic workflows fit findings that determine later tasks or repeated per-item checks.
- Native teams fit sustained peer interaction and direct human addressing when the actual native surface supports it.
- Advisory consultation fits consequential choices or repeated failure that warrants another perspective.
- Adversarial review fits a candidate explanation or implementation with concrete falsifiable claims.
- Long-running goals fit continued native pursuit across turns within the admitted scope; they do not replace supervisor acceptance.

Recommendation: advisor, challenger and acceptance reviewer are different roles. An advisor may use the lead's conversation and help revise the approach. A challenger seeks counterexamples and must report evidence rather than perform hostility. A required independent reviewer receives a fresh context containing the candidate, criteria and permitted evidence. It cannot become independent by switching the producer's role prompt. Different model names do not themselves establish independence.

## Dynamic coordination contract

Recommendation: preserve two levels of coordination. Native exploratory helpers can work within the admitted role/tool/scope envelope without Loam prescribing each call. Required deliverables and consequential actions have explicit supervisor records. Before dispatch of new required delegated work, the supervisor durably admits its task/claim identity, inputs, dependencies and required outcome into the population manifest and returns an admission receipt. The bridge binds that receipt to the actual native child/session/task handle. The receipt includes admitted obligation/plan identity, parent attempt lineage, invocation reservation and workspace claim. A rejection launches no required work. There is one designated native dispatch owner; the supervisor does not independently duplicate a child launched by that bridge. A missing acknowledgement creates an uncertain admission/dispatch to reconcile, not permission to retry blindly. A required child discovered without its admitted binding remains unclassified work and blocks affected completion until reconciled; it cannot be retroactively selected only because its result was favorable. Existing exploratory work may supply evidence only through explicit adoption with original lineage, applicable profile observations and reconciliation. Adoption never grants retrospective permission for external actions. Native launch observation alone cannot add or remove acceptance obligations. Exploratory native children also enter the observable in-flight/accounting inventory, even when they own no separate required deliverable. If the selected native surface cannot establish the required admission/identity contract, the affected dynamic method is unsupported until a bridge prototype resolves the gap.

A native lead may propose expanding an investigation. The supervisor admits that proposal under already granted scope or records a consequential question. The proposal cannot silently weaken an existing criterion or authorize new external actions. A failed or missing child remains a registered unmet obligation. An authorized change in method preserves its rationale and superseded obligations rather than deleting inconvenient evidence.

Recommendation: deliver independent reports before peer critique, then permit discussion and synthesis. Preserve supporting and opposing evidence, original source access scope, and the reason the synthesis preferred one explanation. A skeptical report can be wrong; a majority can share an assumption. Findings need adjudication grounded in evidence, including review of dismissed high-impact findings where the method requires it.

Recommendation: integrate parallel writes from owned workspaces or an established disjoint-write boundary. Disjoint path declarations are planning aids, not OS isolation. An integration owner evaluates the combined candidate, reruns required checks and preserves unrelated changes. No generic instruction to clean the tree by restoring leftover files is carried forward.

## Long tasks, steering and recovery

Recommendation: use a durable execution plan that a continuing lead can update with evidence, completed steps, failed approaches and next work. It references the admitted requirements; it cannot rewrite authority. Keep useful native context and compaction. Do not reset every worker simply because a round ended. Fresh context is required for independence, incompatible retained input, or an explicit recovery choice.

Native goals and native Workflow state are execution aids. Goal completion means ready for Loam checks. Workflow replay or resume does not reverse external effects, restore missing artifacts or prove a later sibling has not already written. Loam retains run/attempt/session identity, queued input, descendant/job inventory, accounting and evidence independently.

Recommendation: record user input before delivery and distinguish persisted, sent, queued, consumed and applied observations. Every execution-triggering input, including a pending approval answer, checks current scope, owner, reservations and steering barriers immediately before delivery. A delivered input capable of starting work belongs in the in-flight inventory. A pause installs an authority barrier even when physical stop remains uncertain.

Continuation prepares a new immutable attempt envelope and revalidates retained native profile/context. Old receipts cannot certify changed models, effort, assets or output destinations. Interrupt receipts do not establish descendant quiescence. If stale queued work cannot be recalled through a supported interface, reconcile old execution before a fresh session or conflicting successor. Missing observability remains a named capability gap.

## Distribution into every seed

Recommendation: ship all reusable infrastructure and generic work methods in the canonical seed payload. Required availability does not mean every method runs on every request. Domain connectors and tool packages activate through declared project bindings. Their setup, compatibility and missing-capability diagnostics ship too. Credentials, live sessions, private memory and personal cache paths do not.

Proposed placement, still reversible filenames:

| Asset | Canonical source/ownership |
|---|---|
| Supervisor, SQLite schema/migrations, evidence and workspace services | Managed seed/.loam/factory/ engine |
| Codex and Claude native bridges, protocol schemas and recorded mechanical fixtures | Managed engine adapters and compatibility assets |
| Generic inquiry, deliberation, experiment, implementation, review, discovery and memory contracts | Managed engine method/role definitions with project-owned extensions |
| User entry, source acquisition, catchup and context delivery guidance | Shared seed/.agents/skills/ with native references/projections; one canonical directive home |
| Native agent/tool/permission projections | Generated from the admitted project profile into the supported native surface; immutable for the active attempt |
| Project goals, decisions, domain methods, tool bindings and overrides | Project-owned configuration/extensions, preserved during update |
| Source pins, licenses and adaptation notes | Managed provenance manifest shipped with adapted assets |
| Operational state and source-linked evidence | Schemas, migrations and explicit setup machinery ship; setup initializes a fresh registered local store and artifact storage. No database or private history is copied from seed. |

Recommendation: reuse small licensed units where they are correct and fit these boundaries. Record repository revision, original file, copied/adapted scope, license/notice, local changes and replacement check. Pattern inspiration is separately labeled. Do not vendor entire cookbook runtimes, demonstration credentials, cloud control planes or model defaults. Package/runtime dependencies are declared and versioned; the generated project must not import the Loam development checkout.

## Complete example: a reproducible experiment report

Illustrative execution, not a task performed in this session.

1. Generate a research project. The full factory, both bridge implementations, work methods, state schemas and setup guide arrive from seed. Explicit factory setup registers a new local instance and initializes its empty store. A missing database in an existing registered instance is recovery, not fresh initialization. The selected native profile establishes its declared tools/authentication/capabilities. The same project can use the other provider through its own admitted profile later.
2. The user asks: make experiment reports show which data produced each result and catch reports that refer to obsolete data. The lead captures the original request and asks an inquiry to compare path/mtime-based identity with content-based identity, including real project callers and dataset conventions.
3. Independent researchers inspect the existing reporting code and relevant original guidance. Their reports are captured before critique. A challenger tries same-path, same-length data changes and asks whether preprocessing/configuration also changes meaning. An advisor can help with the public manifest format. Advisory text is evidence of consultation, not approval.
4. The lead proposes a bounded experiment and records the method: hold report content fixed, vary declared input content and method configuration, preserve raw command outputs, and distinguish validator error from detected stale input. The experiment can reject the proposed design. An unavailable dependency is not a negative scientific result.
5. An engineering decision selects the supported identity/dependency contract and records limits. A ticket names the required behavior and independently checked examples. Its regression criterion must fail on the old behavior; standing integrity checks must already pass. The inquiry's completion was not contingent on generating this ticket.
6. A native implementation worker prepares the manifest and validation behavior. If separation is useful, native specialists own the report producer and validator interfaces, with shared interface decisions admitted first. The dynamic method registers each required output and integrates a combined candidate. Model and effort come from the user's profile, not recipe defaults.
7. The user adds that changed preprocessing must also invalidate a report. If outside the admitted contract, Loam records a successor revision and preserves prior observations. It stops affected acceptance and reconciles old work before execution under the revised method. Compatible independent documentation work may continue.
8. Protected evaluation runs the required cases on the identified candidate. A fresh reviewer inspects both the implementation and its evidence; an adversarial case changes input content without changing length. Missing reports, stale criteria, test execution errors and surviving writers all prevent acceptance. A confirmed defect opens a bounded repair under current authority.
9. Acceptance records the actual candidate, complete criteria receipts and resolved findings. A proposed lesson links the decision, source scope and counterexamples, with applicability to this manifest contract. It does not automatically change factory policy. Publication is a separate authorized action.

Claude can use native subagents/Workflow, with optional actual teams on the interactive route and supported native advisor consultation. Codex uses its own native delegation and continuing threads/goals, plus an explicitly separate consultation role where needed. The same method/evidence contract applies; no fictitious Codex Workflow or server-side advisor API is required.

## Native-specific amendments from original code and documentation

Verified: the Claude source audit distinguishes native advisor, interactive teams, Workflow, goal evaluation and Managed Agents APIs. The Codex source audit distinguishes native app-server/SDK execution from API-agent examples. Exact citations and read scope live in the companion reports.

Recommendation: the admitted method names one continuation owner. The default is supervisor-owned stage continuation with the native host owning the active conversation/tool loop. A selected native goal may own continued turns inside that stage only when its model/effort/evaluator profile is admissible and its lifecycle is observed. The supervisor then refrains from starting a competing turn or repair while that goal is active or uncertain. Reconcile/stop goal ownership before a supervisor repair or successor. A goal's completed/cleared/paused state never accepts the stage or resets lifetime accounting. In particular, do not enable Claude's default goal evaluator when it violates the allowed model family.

Recommendation: use Claude Workflow for bounded admitted stages with explicit expected results and replay semantics. It has no mid-run user input channel of its own. A method-changing correction therefore installs Loam's barrier, interrupts/reconciles affected work, and starts a replacement Workflow stage in the admitted successor work revision/run. Same-method recovery may instead create a new attempt under the existing run. Do not promise that delivery to the parent conversation rewrites a currently executing Workflow script. The script is native execution content, not trusted supervisor code. Missing/null result, unstable script-path scraping, or inaccessible saved state cannot authorize completion.

Recommendation: native Claude advisor is available only with a supported admitted pairing and actual capability evidence. The Fable driver remains the driver. Consultation at a consequential decision, repeated failure or material completion doubt is a reasoned method choice, not a cost-based omission. If consultation is required for a specific decision, enabling the feature is insufficient: require an actual occurrence/identity receipt or use an explicitly admitted separate consultation role. Redacted advice remains redacted; unavailable advice is not invented. Proven occurrence and identity may satisfy an occurrence-only consultation obligation when the admitted method permits redaction. An obligation requiring inspectable advice remains unmet without that content. A separate Codex consultation agent is accurately named as such, not represented as Claude's server-side advisor.

Recommendation: validate premises before checking their consequences. A complete set of accurate answers for the wrong population is an incomplete inquiry. Source inspection establishes the population and critical assumptions; planned obligations retain their origin. Required skepticism covers the admitted claim population, with an explicit unverifiable result. Do not review only positive claims when a false negative or dismissed defect would materially change the decision.

Recommendation: summaries, context indexes, learned lessons and knowledge graphs are derived views. Preserve raw-source access for the lead and reviewer. Compression must retain governing exceptions and uncertainty, not merely shorten the packet. Source observation records distinguish attempted read, successful retrieval, supplied context, actual inspection and substantive support; none alone implies the next. A proposed compiled policy must pass coverage and semantic review against the original authority before admission. An empty valid-looking policy or a model-generated human-approval flag cannot create authority.

## Smallest proof and implementation dependency order

Recommendation: prove the common contract with a generated project, a bounded inquiry/decision, an implementation candidate and independent checks. Start with fake native observations, then exercise each real bridge separately under the same contract. The first slice need not implement every team, goal, advisor or domain backend. Those remain explicit later capabilities with the same distributed method/receipt interface.

The proposed generated-project fixture command is `python3 -m unittest discover -s .loam/factory/tests`. In Loam source the equivalent uses `seed/.loam/factory/tests`. Fixtures ship inside the managed seed engine; they must not depend on root-only Loam tests or personal caches. These paths and commands are future acceptance interfaces, not existing files or test runs.

| Increment | Existing responsibility to preserve or replace | Dependencies | Runnable future check and observable outcome |
|---|---|---|---|
| Portable asset bundle and profile manifest | Replace root-only factory and personal skill resolution | Accepted distribution/update boundary | `python3 -m unittest discover -s seed/.loam/factory/tests -p 'test_factory_distribution.py'`: rendered project remains usable with Loam checkout/personal assets unavailable; project overrides survive update |
| Durable method, obligation and artifact contract | Replace prose/file-name state inference; retain frozen inputs and independent checks | Portable bundle, accepted SQLite/artifact protocol | `python3 -m unittest discover -s seed/.loam/factory/tests -p 'test_factory_methods.py'`: original requirement, admitted method and current complete evidence remain distinct |
| Fake bridge, control ingress and recovery | Replace undifferentiated native result/control assumptions | Durable records, ownership, reservations and evidence spool | `python3 -m unittest discover -s seed/.loam/factory/tests -p 'test_factory_recovery.py'`: lost acknowledgment, late child, stale approval, goal ownership and changed-method Workflow cases do not duplicate or falsely accept work |
| Real Codex and Claude bridges | Replace direct worker_round transport and Claude-shaped Codex projection | Proven config/auth isolation, current protocol, genuine native controls | Same recorded fixtures against each adapter, followed by a separately authorized live inquiry/implementation/check case; actual native evidence must establish profile and lifecycle limits |
| Independent evidence and complete end-to-end run | Preserve useful graders and integration checks; repair missing coverage and cap-to-publication paths | Both adapter contracts, isolated evaluator, source identities | `python3 -m unittest discover -s .loam/factory/tests -p 'test_factory_evidence.py'` in generated project: fail a required check, repair candidate, pass complete checks and fresh review, then record acceptance without publication |
| Dynamic methods and advanced native capabilities | Replace first-round/large-Claude-only branching and hardcoded role effort | Proven required-child admission/identity, basic end-to-end contract | `python3 -m unittest discover -s .loam/factory/tests -p 'test_factory_coordination.py'`: null/missing specialists, teams unavailable, redacted consultation and independent context all retain truthful outcomes |
| Memory, discovery and evaluated maintenance | Extend catchup/handoffs and scattered source guidance | Stable evidence/decision records and work-method extension interface | Memory/evaluation/operations fixture groups in practice registry: stale evidence, lost exception, partial scan and regression block promotion; no automatic policy changes |

An offline fixture proves the reducer and adapter-contract logic only. Native config/auth isolation, auxiliary model policy, task cancellation, direct team steering and actual context loading require live probes before enabling the corresponding managed guarantee. No live probe, model job or runtime implementation is authorized by this design document.

Supplemental source consequences: a source-inspected memory tutorial diagnoses concurrent mutation where its displayed code serializes the writes, then asks the model to retain that diagnosis. Memory promotion therefore needs source verification and an applicable check, not repetition. Clearing re-callable tool output is not lossless when external state can change. Preserve historical evidence before dropping context. Normalize memory paths before root-operation checks and enforce component/OS boundaries rather than string prefixes. Optional organization accounting imports retain pagination completeness and malformed values explicitly; they cannot replace native run records or grant budget authority. These cases are integrated into the practice registry and later memory design obligations.

## Final transport comparison after the SDK source check

Verified: the official Python Codex SDK itself uses local app-server. Its inspected public/low-level control paths are documented in cookbook-codex-audit.md, with a separate openai/codex source pin and exact read scopes. The source review found synchronous pending-approval handling on the sole reader thread, high-level omissions of the approval handler/full start receipt, broader observation needs than a turn stream, environment overlay rather than isolation, and low-level Goal helpers whose replacement/cleanup behavior cannot serve as Loam authority. This is source evidence, not a runtime reproduction.

| Choice | Recommendation and reason | Reconsideration check |
|---|---|---|
| Narrow direct Codex app-server client | Preferred for the full managed profile: continuously capture raw events/requests, durably queue pending decisions and reply without blocking observation; retain explicit launch/configuration ownership. It keeps native reasoning and tools. | Conformance fixtures establish versioned requests/events, pending approval plus ongoing child events, stop/reconnect, effective profile and Goal ownership. |
| Official Python Codex SDK as app-server client | Credible alternative, not a competing agent architecture. Current inspected interfaces need adaptation/private access for this full control contract, so not the first implementation choice. | Reconsider when supported public interfaces expose asynchronous durable approvals, full observations and required lifecycle controls while preserving the same tests. |
| Codex TypeScript SDK or CLI exec | Native batch/streaming alternatives for explicitly compatible bounded work. No claim that streaming alone provides the full interactive approval contract. | Admit only the capabilities established for that stage; uncertain prior execution is reconciled before transport changes. |
| Claude official TypeScript Agent SDK open-input query | Preferred Claude bridge with supported native conversation, subagent, interrupt and task controls. Queue cancellation and interactive teams remain distinct capability limits. | Existing native-claude-evidence.md probes establish real config, user provenance, descendant stopping and stale-queue behavior. |
| Cloud Agents APIs / Agents SDK manager / exec-server service | Named optional future service integrations, not mandatory every-seed runtime or native-loop replacement. Some cookbook orchestration examples are archived. | Separate service/source/authority/runtime audit when a project actually needs the remote capability. |

Recommendation: the Codex reader appends raw input and dispatches a pending decision to a separate authority-processing queue while continuing to drain the native stream. It must not wait synchronously for the human on the only event reader. Replies use the current durable request/action/revision identity. Preserve external/source/agent messages as lower-trust data through supported native message types; never manufacture a user correction from them. Native Goal activation requires explicit authorization through the selected work method, not merely the existence of a task.

The adjacent source supplement also tightens artifact dependencies and feedback identity: a downstream stage consumes the actual admitted upstream artifact hash, not merely a similarly worded query after an earlier stage ran. User feedback and evaluation bind to the exact displayed output and run; rerunning to obtain a trace would be a different execution. Failed memory consolidation retains unpromoted candidates and cannot promote temporary notes by falling back to append-all.
