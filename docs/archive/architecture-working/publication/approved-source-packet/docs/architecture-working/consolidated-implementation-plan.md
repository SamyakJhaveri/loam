# Loam Factory Consolidated Implementation Plan

> **For agentic workers:** After explicit authorization to implement, use the applicable executing-plans workflow task by task. Retain one integration owner and one full-check owner for each final source snapshot. Independent bounded investigation/review follows the user's standing authority and repository rules. This document authorizes no runtime work or publication.

**Goal:** Give every generated project a maintainable native Claude/Codex factory that operates locally on Mac/Linux, directs Linux agents/GPU work from the Mac, and preserves evidence, ownership and useful corrected memory through failures and updates.

**Architecture:** One TypeScript implementation ships from seed as compiled JavaScript. The project supervisor owns local SQLite authority; execution hosts retain native/process observations and artifacts. SSH connects the same execution contract to a persistent Linux runner, whose job ledger records execution facts rather than project acceptance decisions.

**Tech stack:** Accepted TypeScript/Node, SQLite, native Claude TypeScript bridge and direct Codex app-server binding; existing Copier distribution; narrow Mac/Linux platform mechanisms and Linux service management. Exact supported dependency versions are outputs of qualification, not assumptions copied from current machines.

## Global constraints

- Follow the accepted [source-grounded delivery workflow](delivery-workflow.md): source packets from the supplied references, fresh worktrees from current main for each implementation step, actual opposite-model plan and finished-work reviews, verified merge before the next dependent step. Use native loops, dynamic workflows, advisor consultation and multi-agent patterns where appropriate throughout implementation and testing.

- Runtime implementation begins only when the user explicitly asks. This is a consolidated delivery plan, with code authored and tested during execution. Proposed paths, interfaces and commands below are not existing APIs or passing tests.
- Support Mac and Linux, initially this Mac and personal `jhaveris`, with explicit enrollment of replacement machines. Keep GPU handling simple: queue by default with fail-fast available, no multi-user scheduler or scheduling questionnaire.
- Accepted mixed offline policy: already started fixed GPU jobs continue within agreed limits; native agents default to interruption. Detected loss blocks new starts/approvals immediately; the recorded lease deadline bounds interruption. No automatic new offline jobs or budget extension.
- Preserve TypeScript, native reasoning/tools/delegation, actual lead authority and user-selected model/effort. The eligible session lead decides improvement adoption; fake/native completion/evaluator PASS cannot substitute for that decision.
- Preserve option C, every curated Loam method through its mapped destination or named successor, and the admitted cross-project additions. Personal caches, source projects and private data are not seed dependencies.
- No missing registered store becomes fresh setup. No uncertain dispatch becomes a retry. No worker gains project-store, protected runtime, check-receipt or operator-SSH authority.
- Keep project choices, extensions, history and active input/runtime snapshots through updates. Source acceptance, release, installation and publication are separate actions.
- Every implementation step in this campaign, including its documentation, tests, build scripts and gate changes, uses a fresh current-main worktree and the full delivery cycle. Unrelated documentation maintenance may follow repository policy; any resulting main movement still invalidates an open step's old integration basis. Preserve current untracked design files before creating another checkout. No blanket stage, reset, clean or retirement of the old controller.
