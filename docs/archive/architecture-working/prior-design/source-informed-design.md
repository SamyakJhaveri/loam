## Research evidence and its limits

Verified: X08 reports failure cases in qualitative research attempts; it does not establish a universal model ceiling. X09 binds claims to evidence but its implementation appendix still uses imperfect numeric, abstract-support and textual-overlap checks. X10 distinguishes execution, correctness and performance in a specialized kernel benchmark; its results depend on task and evaluation conditions. Exact read scopes are in sources-research-memory.md.

Recommendation: use these sources to design falsifiable checks, not to import benchmark confidence. Record method revisions when implementation changes the proposed method. Preserve failed or interrupted experiments separately from a valid negative conclusion. Check whether a real citation supports the specific assertion, whether reported numbers come from the correct run, and whether code implements the claimed method. Structural evidence edges help review but do not prove those relations. Research completion can be supported, refuted, mixed or inconclusive, while execution status independently records whether the inquiry was completed, interrupted or blocked.

## Consequential choices to discuss next

Recommendation: keep the accepted native-supervisor split. Its boundary is clearer after the source reads: native hosts decide how to investigate and execute within admitted scope; Loam decides durable authorization, current evidence, retries, recovery and acceptance.

Recommendation: treat state storage as a correctness choice now. A single-writer journal remains credible if append, commit, projections, lock ownership and recovery are explicit. A transactional local store is credible because admission, attempts, accounting and acceptance update related records. Do not prefer files merely because old Loam used files. Compare deployment prerequisites and crash fixtures before settling the implementation. The project evidence archive can remain readable files with either state backend.

Recommendation: start project memory with source-linked records and a rebuildable local index. Native personal memory remains an optional context aid. The exact retrieval backend and consolidation policy remain open until a held-out retrieval/correction test demonstrates need. See memory-design.md.

Recommendation: full factory availability and gradual activation are compatible. Every seed gets the generic research, deliberation, evidence, recovery, learning and discovery machinery. Domain packs, media acquisition tools, external accounts and schedules have explicit readiness and project choices. None is silently supplied by this Loam checkout.

## Cross-critique

Verified: a reader independent of loop-design.md compared it with official/native cookbook reports and found missing explicit clauses for model observation, Workflow replay/null coverage, goals accounting and team plan approval. Those clauses and corresponding failure fixtures were added to loop-design.md. A follow-up review found two further gaps: detected model violations needed a mandatory interruption/readmission transition, and intended context packets could not prove native inclusion or source reading. Both contracts were corrected. Loop-repository analysis also distinguished local committed-receipt replay from repeating an externally effective operation; the design retains unknown outcomes when readback cannot resolve them.

Remaining source limits and untested behavior are listed in reference-reading.md. These recommendations do not convert historical review proposals into accepted product features.
