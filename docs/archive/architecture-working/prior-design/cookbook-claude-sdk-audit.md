## Concrete native SDK findings

All “Verified” statements in this section describe the pinned source, supplemented only by the linked current native contracts. Proposed repairs are Loam design choices, not claims about an existing implementation.

**SDK 00, research.** Verified: the native SDK manages the research loop, supports continuing investigation in a client session, and lets a source-driven inquiry choose searches and local multimodal reads. This supports native research as a first-class factory method. A system prompt requesting citations does not establish that citations entail each claim. The companion's `continue_conversation=True` does not bind a particular session; a concurrent factory must use explicit session identity. A stored source list, original question, acquisition failures and claim-to-evidence links belong in durable artifacts.

**SDK 01, chief of staff.** Verified: project instructions orient the agent, role files define delegation, command templates encode repeatable methods, and hooks record local activity. The plan-capture helper selects the newest global plan file by age and length, with no session ownership check. It also treats attempted Write content as a possible plan without establishing successful persistence. This cannot be an admitted factory plan receipt. The Edit hook path in `settings.local.json` ends in `report-tracker.py123`, while the companion file is `report-tracker.py`. The tracker rewrites a bounded JSON history and swallows errors; the script logger can default an unrecognized response to success. Neither is an authoritative audit ledger. A global instruction file is working context, not proof that the source corpus was inspected.

**SDK 02, observability.** Verified: domain MCP tools provide useful repository and incident access. Broad MCP preapproval plus a read-only prompt does not remove mutation tools. Returning an empty MCP map when a token is absent silently changes capability. Loam needs a declared required-tool check, explicit privilege scopes and visible unavailable integrations. Credential availability does not authorize every action the credential can perform.

**SDK 03, SRE.** Verified: hypothesis-driven investigation, baseline/fault/restored comparisons and explicit investigation/remediation phases are useful methods. The same options preapprove mutation tools during an investigation whose prompt says not to fix. The notebook shell handler permits broad Docker executables; the companion tightens immediate subcommands but admits nested compose operations. This is not a narrow repair capability. Generated hook scripts read `input` rather than native `tool_input` and use exit status 1 without a blocking JSON decision. Current [hook input and exit contracts](https://code.claude.com/docs/en/hooks) show that these do not enforce the intended PreToolUse gate. The notebook's cleanup checks absence of one bad substring rather than parsing and comparing the exact restored value. Its positive label is stronger than its evidence. Repair permissions in the adapter; keep operational methods in a skill and project integration bindings in configuration.

**SDK 04, migration.** Verified: input checks before launch and output checks after results can be deterministic code outside the model. Native subagent delegation leaves the lead in control and is not equivalent to an API framework handoff. Prompt fragments and regex response checks are insufficient semantic acceptance. Preserve the native control surface instead of reproducing another framework's runner semantics. Historical setup/model names are not defaults for Loam.

**SDK 05, session browser.** Verified: local listing, transcript inspection, rename/tag, fork and delete are session-storage operations. Forking remaps message IDs; it does not isolate filesystem effects. The notebook says an empty `allowed_tools` list disables tools, but its calls only remove preapprovals. Current [permission documentation](https://code.claude.com/docs/en/agent-sdk/permissions) explicitly distinguishes available tools from approved tools. Preserve this contradiction in the design record. Native session metadata can support a browser, while richer attempt state, lineage, authority and evidence retention remain in SQLite. A soft-hide operation and an irreversible transcript delete must stay distinct.

**SDK 06, vulnerability research.** Verified: bootstrap threat model, owner interview, investigation, fresh triage and reporting form a reusable inquiry method with task-specific standards. Example owner replies are fixtures, not authorization. Its JSON schema is embedded in prompts and parsed with `json.loads`, not supplied as validated structured output; the README's schema-conformance claim exceeds the code. Read/Grep preapproval and Bash denial do not establish a complete read-only tool set. The findings still need reproduction or explicitly bounded evidence; a suggested sanitizer run is not a verified result.

**SDK 07, hosting.** Verified: the notebook usefully separates process, conversation and deployment lifecycle. The server says its WebSearch allowlist removes Read, but `build_options` sets `allowed_tools` without constraining tool availability. Its session map locks writes but does not serialize two first requests for the same external session, so both can launch distinct native sessions. Mapping updates become visible in memory before durable persistence. Raw output can be streamed before the native-session mapping is saved. `run_once.py` can return success when no result was seen. The body limit checks Content-Length, not the bytes actually consumed. These examples need durable ingress ownership, launch reconciliation and terminal-result validation before reuse. Their narrow hosted search profile is not an appropriate blanket configuration for Loam's research driver.

**SDK 08, dynamic workflows.** Verified: this is native Claude Code Workflow, not merely a hand-built API agent loop. The source demonstrates model-authored scripts, schema-bearing native agent calls, parallel barriers and per-item pipelines. Code variables can hold intermediate results without stuffing all material into the lead's context. Subagents inherit a shared working directory; concurrency does not provide file isolation. Regex extraction of task IDs/script paths is explicitly a demo convenience. A launch result is not a complete workflow result. The prompt challenges confirmed claims, although surrounding prose says each verdict gets a skeptic. Thus the required verifier population and conditional skeptic population must be recorded separately. Missing evidence needs an unresolved status, not an automatic contradiction. See the prior audit's concrete null-filtering and missing-skeptic defects in saved script output. Current [Workflow documentation](https://code.claude.com/docs/en/workflows) bounds cached replay to the same session and distinguishes genuine human-origin opt-in from generated or scheduled prompts. Loam must retain honest input provenance, admitted script identity and its own durable obligations.

**Scheduled reviewer.** Verified: this is the strongest notebook example of separating `tools` availability from `allowed_tools` preapproval, using unattended permissions, retaining explicit session IDs, structured results and typed terminal errors. A cold baseline followed by fresh file discovery on each resumed pass prevents continuity from hiding new files. However, the companion checks only whether previous/current finding-ID sets overlap, rather than requiring coverage of every previous finding. It persists the new baseline before this continuity check; a broken link can print a marker then still return success. It also accepts the verdict field without cross-checking contradictory nonempty findings. Atomic rename protects an individual file update, not the complete acceptance transaction. This is a continuing reviewer, not evidence of independent fresh-context grading. Its hostile-repository isolation is a specific role profile, not the full factory driver's default.

## Cross-cutting research, memory, skills and policy

**Working memory.** Verified: `misc/session_memory_compaction.ipynb` implements its own Messages API history summarization. It is not a native SDK compaction extension. Preserve original requirements, later corrections, unresolved work, failed approaches and source references in any compacted context packet, with links to original records. The cache helper flattens content to a text block and would not preserve general multimodal/tool transcripts. Background summary work has no generation token to reject a stale completion after compaction changes indices; a timed join can leave a writer active. Loam should keep native compaction and store authoritative task/evidence records separately, rather than copying this second context loop. Approximate token counts do not establish complete spend accounting.

**Evaluation design.** Verified: `building_evals` separates deterministic, model and human evaluation; `generate_test_cases` produces candidate cases; `metaprompt` offers a starting prompt transformation, not a validated research method. Preserve frozen criteria, independent evidence and human-calibrated rubrics. Synthesized tests are not automatically golden truth. `zip(strict=False)` in the eval helper can drop unmatched work. Malformed/empty model grades must be evaluation errors, not smaller denominators or automatic passes. Tool-evaluation's source loop is serial despite parallelization prose, dispatches through `eval`, and inspects only the first tool call. The companion patterns audit owns the fuller tool-evaluation classification.

**Agentic-search evaluation.** Verified: the API benchmark uses server tools, container/context continuation and pause-turn handling. These are not automatically identical to native Bash/WebSearch capabilities. Its instructions preserve the original query and answer shape. The helper accepts the whole response when an expected result tag is absent, despite the notebook describing tag-only grading. Its truth denominator comes from the grader's emitted items, so omissions can shrink the target. Record expected source/case IDs before execution, retain missing cases, and freeze grader criteria and model policy. No performance numbers in the notebook were reproduced here.

**Multimodal research.** Verified: `using_sub_agents` uses parallel Messages API calls, not native Agent or Workflow. Failed PDF reads can disappear before synthesis. Its chart generation executes model-produced Python directly in the host. The reusable method is independent per-document analysis followed by evidence-aware synthesis, with every missing source explicit. Any future experiment/code generation needs the admitted native experiment workspace and captured artifacts. Its cheaper-model routing conflicts with the user's allowed family and effort policy.

**Citations.** Verified: API citation blocks encode source locators, but location validity does not prove claim support and does not prove identical native SDK output. The display helper can merge same-title, same-text citations from distinct documents. Use immutable source IDs/digests plus locators and claim IDs. Text-only PDF extraction is not chart verification. Preserve source acquisition and analysis as distinct steps.

**Skills.** Verified: the three skill notebooks show API-container skills, versions, progressive context, composition and file retrieval. They are not instructions to install native filesystem skills through that API. “Latest” is not a reproducible version. The financial example's spreadsheet, deck and PDF prompts do not pass the prior generated artifact through the chain, so three downloaded files are not proof of coherent shared analysis. `file_utils.py` joins provider filenames to an output directory without an explicit confinement check, defaults to overwriting, and does not establish artifact hashes or complete content validity. The custom-skill helper examines only an initial list page and may turn an error into an empty list. Title-based cleanup is not provenance-bound deletion. Current [native skill documentation](https://code.claude.com/docs/en/agent-sdk/skills) distinguishes filesystem sources from a list of invocable skill names; a SKILL.md path is not such a name. Direct command dispatch and readable skill files are separate surfaces. An init skill list alone cannot prove which content was loaded or restrict every access path.

**Deterministic policy.** Verified: the content-moderation guide compiles human prose into a rule artifact, statically validates it, extracts typed facts/judgments, then uses a pure rule evaluator with true/false/unknown outcomes and traces. This separation is directly useful. But `validate_document({})` returns no errors by source inspection because all expected sections default to empty containers; it does not prove clause coverage, policy meaning, authority, or a nonempty ruleset. Derived model judgments remain nondeterministic inputs even when evaluation is deterministic. The notebook uses a human golden ruleset for subsequent demonstrations. Its compiler attempt records hold error summaries, not the whole claimed transcript. Appending an additional rule can omit newly uncompilable clauses; cached compiled files are keyed by domain name rather than full policy/schema/compiler identity. Loam should accept human-authorized versioned policy, preserve every policy clause's disposition and unknown outcome, and keep generated policies as reviewable proposals. Generated or learned rules must never replace human authority automatically.

**Knowledge graphs.** Verified: typed entities and relations, resolution proposals, per-edge source documents and neighborhood-based synthesis provide a useful derived research index. They do not justify replacing SQLite or source artifacts. Fetch/extraction failures are skipped. Name-only deduplication can discard different descriptions of homonyms; the global alias map is not keyed by entity type or source identity. Unmatched aliases disappear, and the notebook acknowledges over-merging. Graph serialization omits source-document metadata, although answer prose promises traceability. A connected component is not proof of correct entity resolution. The summary prompt prefers specific claims when evidence conflicts; specificity alone is not a sound conflict rule. The standalone evaluator ignores relation predicates and averages only successful documents, so it cannot establish full semantic relation quality. Preserve raw mentions, typed stable identities, merge decisions with provenance, contradictory assertions and missing documents. Test resolution coverage and entailment against a frozen source population before accepting graph-supported claims.

## Corrections and refinements to prior design

Verified: the current prior `native-adapter-design.md` and `native-claude-evidence.md` already correctly distinguish `allowedTools` from tool removal, native sessions from durable acceptance, genuine human provenance, and native memory from evidence authority.
