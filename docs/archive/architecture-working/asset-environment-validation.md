## Self-attack and completeness

- What input breaks this? A same-name external skill could overwrite curated behavior, or a copied skill could quietly activate broad permissions. The catalog/conservation contract prevents silent substitution; source references are non-executable `.txt` files outside native asset roots. Activation remains a separate implementation gate.
- Which path did I not check? Most non-shortlisted benchmark definitions received metadata/dependency review, not a full behavioral audit. Remote declared plugins, source program tests, native account flows and environment probes remain unperformed and explicitly tracked.
- What changed without runtime tests? Design records, metadata inventories and selected inactive text. No future engine behavior is claimed. Source scripts were not run simply to validate their packaging.
- Which claim lacks evidence? The local-first recommendation is a design judgment. The whole native-process protection and feature compatibility are labeled assumptions/probe gates, not verified properties. A guest VM also requires internal supervisor/native separation.

Second attack: each staged external reference now maps to ASSET-02, ASSET-03, ASSET-04 or ASSET-05. The DistBench readiness variant has an explicit comparison task.
